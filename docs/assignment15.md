# Умножитель двух 15-разрядных чисел с плавающей точкой

## Принятый формат

По согласованному условию 10 разрядов мантиссы включают знак и 9 разрядов
дробной части. Порядок занимает 5 разрядов и записан в дополнительном коде.

| Разряды слова | Содержание |
| --- | --- |
| 0–8 | Беззнаковое целое F, дробь F / 512 |
| 9 | Знак мантиссы S |
| 10–14 | Знаковый порядок E, диапазон −16…15 |

Значение числа: **X = (−1)^S · (F / 512) · 2^E**.
Входы нормализованы: F = 256…511, либо F = 0 для нуля.
Предположения о кодировании согласованы отдельно: в кратком тексте задания
они не определены. Это учебный формат, не IEEE 754.

## Обоснование

1. Знак произведения равен XOR знаков множителей.
2. Модули мантисс перемножаются как два 9-разрядных целых числа.
   Каждый частичный продукт Pij = Ai AND Bj имеет вес 2^(i+j).
   Суммирование частичных произведений даёт 18-разрядное P = FA · FB.
3. Для нормализованных ненулевых входов P / 2^18 находится в [1/4, 1).
   Если P17 = 1, дробь уже нормализована. Если P17 = 0, её нужно удвоить,
   а порядок уменьшить на единицу. Поэтому SHIFT = NOT P17.
4. Выходная дробь FY = P >> (9 − SHIFT). Выбираются P17…P9 либо P16…P8.
   Выбор каждого бита реализован двумя AND и одним OR, без блока MUX.
   Младшие биты отбрасываются: округление по модулю к нулю.
5. Порядок EY = EA + EB − SHIFT вычисляется в 7-разрядном дополнительном коде.
   Семь разрядов нужны для нижней границы −16 −16 −1 = −33.
   При корректном результате старшие разряды E6, E5, E4 равны.
   RANGE_ERR = (E6 XOR E5) OR (E5 XOR E4).
6. Если любой модуль равен нулю, выходные мантисса, знак, порядок и RANGE_ERR
   обнуляются. Отрицательный ноль не формируется.

Сумматоры раскрыты до вентилей. Полусумматор: S = A XOR B, C = A AND B.
Полный сумматор: P = A XOR B, S = P XOR Cin,
Cout = (A AND B) OR (P AND Cin). Это два XOR, два AND и один OR.
Высокоуровневых арифметических блоков в рисунке нет.

При выходе порядка за диапазон RANGE_ERR = 1; 15-разрядное слово Y в этом
случае не является допустимым результатом. Поле порядка содержит младшие
пять разрядов расчёта. Насыщение, денормализованные числа и специальные
значения не реализованы.

## Регистрация и синхронизация

RA00…RA14 и RB00…RB14 — входные D-триггеры, RY00…RY14 — выходные.
RSYNC и YSYNC передают отдельный бит валидности; RERR регистрирует RANGE_ERR.
Всего 48 D-триггеров. Все тактовые входы физически соединены с общей цепью CLK.

На фронте n захватываются A, B и SYNC_IN. На фронте n+1 появляются их Y,
RANGE_ERR и SYNC_OUT. Новая пара операндов может поступать на каждом фронте.
SYNC=0 обозначает невалидные данные, но не останавливает регистры.
Сброс не задан; до первой зарегистрированной единицы SYNC_OUT выход игнорируется.
Период CLK выбирается больше задержки комбинационной цепи с учётом setup/hold
реальных триггеров. Программная проверка логики не является расчётом тайминга.

## YAML и рендер

```powershell
python -m pip install -e ".[test,layout]"
python -c "from nodejs_wheel import npm; raise SystemExit(npm(['ci', '--ignore-scripts']))"
python -m schematic_renderer.assignment15
```

Последовательность работы:

1. `output/assignment15/assignment15.logic.yaml`: формат, группы элементов,
   отдельные вентили и триггеры, полный список электрических соединений.
2. `output/assignment15/assignment15.yaml`: та же логика, абсолютные координаты
   и промежуточные точки каждого провода, рассчитанные ELK.
3. Рендер читает именно второй YAML и создаёт PNG и SVG единой схемы.

```powershell
python -m schematic_renderer output/assignment15/assignment15.yaml -o output/assignment15/assignment15.png
python -m schematic_renderer output/assignment15/assignment15.yaml -o output/assignment15/assignment15.svg
```

Для повторного рендера подготовленного YAML Node.js и ELK не нужны.
Для размещения применяется [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)
с фиксированными выводами и ортогональной трассировкой.
Чтобы заново разместить изменённую логическую схему:

```powershell
python -m schematic_renderer.prepare output/assignment15/assignment15.logic.yaml -o output/assignment15/assignment15.yaml
```

Все внутренние соединения проведены непрерывными линиями. Чёрная точка означает
электрическое соединение; дуговая перемычка означает пересечение без контакта.
Общие отрезки допустимы только для одной и той же электрической цепи.
Подписи внешних A/B, Y, SYNC и RANGE_ERR находятся на выводах триггеров.
`CLOCK` обозначает внешний тактовый сигнал, а не схему генератора частоты.

Холст автоматически охватывает все блоки, выводы и маршруты проводов с полями.
Размер элементов не зависит от количества блоков: основной шрифт 24 px,
подписи 20 px, минимальный блок 180 × 104 px. Подгонки под страницу нет.
`canvas.scale` увеличивает весь экспорт, включая размеры PNG и SVG.
Просматривайте полную схему при масштабе 100%, а не в режиме «вписать в окно».
Уменьшенный `overview.png` создаётся только по явному запросу:
`python -m schematic_renderer.assignment15 --preview`.

## Плотность размещения

В `layout_groups` перечислены вентили каждого одноразрядного сумматора.
Это группы для компоновки: на итоговом рисунке по-прежнему видны отдельные
AND, OR и XOR, а не составные арифметические блоки. ELK размещает группы
вместе и прокладывает все внутренние и внешние связи.

Затем проход уплотнения сокращает свободные промежутки по вертикали и
горизонтали. Он перемещает блоки целиком и сохраняет относительные координаты
выводов, прямые участки и порядок пересечения проводов. Ограничения на зазоры
защищают подписи, блоки и дуги пересечений. Входные и выходные банки триггеров
остаются выровненными. Шрифты и размеры блоков при уплотнении не изменяются.

Уплотнение включено в обычную генерацию. Отдельно его можно применить к
существующему подготовленному YAML:

```powershell
python -m schematic_renderer.compact input.yaml -o compact.yaml
```

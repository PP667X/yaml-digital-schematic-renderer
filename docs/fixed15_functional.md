# Задание 2: функциональная схема умножения с фиксированной точкой

Отдельная схема того же уровня детализации, что и `float15_functional`:
регистры, сдвиги, сумматор-вычитатель, счётчик и автомат управления.
На изображении только схема: без заголовка, формул и поясняющих текстовых блоков.
Все внутренние соединения непрерывные. Точки обозначают соединения,
перемычки на пересечениях обозначают отсутствие контакта.

## Формат

- A и B: 15 бит в дополнительном коде, из них 5 дробных.
- Значение входа: `signed15(code) / 32`, диапазон от -512 до 511,96875.
- Y: полный 30-битный результат в дополнительном коде, 10 дробных бит.
- Значение выхода: `signed30(code) / 1024`.
- SYNC является отдельным битом действительности, а не частью числового слова.

Порядок и нормализация не нужны: точка всегда находится после пятого бита
на входе и после десятого на выходе. Округления и усечения нет. Диапазон
целых произведений -268419072..268435456 помещается в знаковые 30 бит,
поэтому флаг переполнения не требуется.

## Узлы

| Узел | Назначение |
| --- | --- |
| RA, RB | Принимают операнды по CAP. RA дополнительно хранит SYNC. |
| RM | 30-битный регистр множимого: загрузка A со знаковым расширением 15 -> 30; сдвиг влево на каждом рабочем шаге. |
| RQ | 15-битный регистр множителя: загрузка исходного кода B; логический сдвиг вправо. Q0 последовательно выдаёт все биты B, включая знак на последнем шаге. |
| SM_M | 30-битный сумматор-вычитатель. SUB=0: ACC+M; SUB=1: ACC-M. |
| ACC | 30-битный накопитель. INIT очищает его, ACC_EN разрешает запись только при Q0=1. |
| CNT | Четырёхбитный счётчик с загрузкой 15. LAST означает значение 1 до фронта последнего шага. |
| CTRL | Автомат IDLE, INIT, RUN, WRITE, DONE; формирует загрузки, сдвиги, SUB и готовность. |
| RY | Выходной регистр: 30 бит результата и один сохранённый бит SYNC. Запись по SAVE. |

## Умножение знаковых чисел

Если b задан в дополнительном коде, его числовое значение равно:

`b = sum(B[i]*2^i, i=0..13) - B[14]*2^14`.

Поэтому достаточно последовательно прибавлять сдвинутое a для единичных
битов 0..13, а на последнем шаге вычитать его для единичного знакового бита 14.
Начальные значения: `M=sign_extend(A,30)`, `Q=B`, `ACC=0`.
На каждом шаге сначала используются текущие Q0 и M, затем M сдвигается
влево, Q вправо, счётчик уменьшается. На 15-м шаге `SUB=1`.
Если Q0=0, накопитель не перезаписывается независимо от SUB.

Все операции выполняются по модулю 2^30, что даёт правильный дополнительный
код полного произведения. Такой алгоритм не требует вычислять модуль
отрицательного операнда и корректен для минимального кода -16384 (число -512).

## Управление

Все регистры и автомат имеют общий положительный фронт CLK и синхронный
активный единицей RESET с наивысшим приоритетом. Выходы CLK/RST контроллера
являются прямыми распределительными копиями внешних входов, не тактами
с дополнительным стробированием.

1. IDLE: START=1 на фронте n принимает A, B, SYNC через CAP.
2. INIT: фронт n+1 загружает RM/RQ, очищает ACC, загружает CNT=15.
3. RUN: фронты n+2..n+16 выполняют 15 шагов. `ACC_EN=RUN and Q0`,
   `SUB=RUN and LAST`, `STEP=RUN`. LAST проверяется до фронта.
4. WRITE: на n+17 записывается готовое произведение и сохранённый SYNC;
   автомат переходит в DONE, OUT_READY=1.
5. DONE удерживается до START=0, затем следует IDLE. Во время BUSY запросы
   START игнорируются. BUSY активен в INIT, RUN и WRITE.

RY удерживает выход до следующего SAVE или RESET. SYNC не заменяет READY:
он переносит входную отметку действительности, а READY сообщает завершение.
Внешние стрелки направлены наружу по требованиям; IN_/OUT_ различают
направление передачи сигналов. Внутренних разрывов нет.

## Файлы и проверка

Готовое описание с координатами и маршрутами:
`examples/fixed15_functional/fixed15_functional.yaml`.
Исходная структура до автоматического размещения:
`examples/fixed15_functional/fixed15_functional.logic.yaml`.
Первая функциональная схема и прежние вентильные варианты не изменены.

Повторный рендер из корня проекта:

```powershell
python -m schematic_renderer examples/fixed15_functional/fixed15_functional.yaml -o output/fixed15_functional/fixed15_functional.png
python -m schematic_renderer examples/fixed15_functional/fixed15_functional.yaml -o output/fixed15_functional/fixed15_functional.svg
```

Обычный повторный рендер не требует ELK/Node.js. При новой автоматической
компоновке через `schematic_renderer.prepare` нужно пересчитать координаты
внешних стрелок, потому что подготовка удаляет графические примитивы.

Проверки: `python -m pytest tests/test_fixed15_functional.py -q`.
Проверяются связи, разрядности, трассы, внешние стрелки, 2169 полных
транзакций, задержка, SYNC и сброс. Дополнительно проверяются все 32768
кодов множителя для пяти характерных множимых, включая оба края диапазона.
Поведенческая модель читает реальные соединения YAML и реализует явно
описанные контракты блоков; генератор не является HDL-симулятором, а тесты
не проверяют физические задержки реальных компонентов.
